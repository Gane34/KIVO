# Forecast Validation Protocol

## Status

Prospective protocol for the three separate PhysioTwin tracks. No suitable real T2D time-series dataset or verified data license is present in the repository. Until one is acquired with documented terms, real-data accuracy, calibration and event prediction are **not evaluable**. Results from the current ODE-generated CGM are synthetic model-consistency checks only.

## Track Separation

| Track | Permitted question | Data and interpretation |
|---|---|---|
| **A. Mechanistic physiology** | Do declared flux balances and closures reproduce independent physiology in a declared domain? | Requires supported equations/parameters, independent measurements and identifiability review. The current model is a software fixture only; do not include it as a meaningful predictor unless it passes those gates. |
| **B. Data-driven forecasting** | How accurately can past glucose observations predict future glucose in a declared population? | Requires permissioned longitudinal glucose data and subject-level splits. Keep T1D method benchmarks separate from T2D claims. No learned model until cohort size and diversity support it. |
| **C. Synthetic software experiments** | Are generation, time alignment, model execution and metric code deterministic and correct for known synthetic processes? | Use known generator truth for software tests and algorithm recovery. Label all metrics synthetic; no physiological/external-validation inference. |

Store track ID, source/provenance, model/config version and evaluation split in every run manifest. Do not pool metrics across tracks or let a synthetic status be rendered as a patient risk estimate.

## Data Eligibility Gate

Before any real-data evaluation, record and review:

- Authoritative source, accession/URL, retrieval timestamp, checksum, license/data-use terms, redistribution restrictions and transformation lineage.
- Population (including diabetes type), subject IDs, longitudinal sampling frequency, units/specimen/device, missingness, duplicate handling, sensor quality and the exact observation/forecast timestamps.
- Availability and alignment of meal timing/carbohydrate records, insulin/medication records, and any relevant clinical/reference measurements. Do not infer these covariates from labels or unrelated data.
- Consent/privacy/governance conditions, de-identification status, permitted purpose and whether artifacts can be made public.
- Independent reference event labels and their definition if adverse events are evaluated. A label generated by the same predictor or its threshold rule is not independent validation.

Current audit finding: repository contains no raw patient CGM or glucose observations. Profile attributes and streams in `synthetic.py`/`observations.py` are scripted; no sensor is connected. GSE153792 is transcriptomic and is unsuitable for glucose forecasting. Published Padova/R1/R6 materials are methodological evidence, but the checked routes did not provide the participant-level data and exact implementation material needed here. No open-data license is established. A T1D CGM cohort may be separately assessed for forecasting methods if eligible; its results cannot validate a T2D physiological model or establish T2D performance.

## Forecast Task And Origins

For eligible longitudinal streams, predeclare forecast origins and horizons of 30, 60 and 120 minutes when the sampling frequency supports them. Use rolling origins on each test subject after a minimum history that is declared before evaluation. Preserve the original timestamps; define horizon endpoints in elapsed time and do not silently substitute an adjacent sample when the exact horizon is absent. Do not forecast beyond a subject's valid observation span.

At origin $t$, every forecast, feature, state estimate, normalization statistic, parameter fit and model choice may use only records with timestamps $\le t$. Future observations are held in a separate evaluator-only object. Any meal or insulin future input may be supplied only if it was genuinely known at $t$ under the task definition; otherwise it is excluded. Record forecast origin, target timestamp, history count, data-quality state and model provenance per row.

Use one common eligible origin/target set for every model compared at a given subject and horizon. If one model cannot produce a value, report the reduced common sample or explicitly report a separate comparison; never allow the model to benefit from easier timestamps. All errors are calculated in the same stated glucose unit, preferably mmol/L after a recorded conversion.

## Split, Fitting And Leakage Controls

1. Assign whole people/subjects to train, validation and test before extracting rolling windows. No timestamp or window from a person may cross partitions. If only one or a few synthetic profiles are available, describe the split as a synthetic scenario test, not patient-held-out validation.
2. Keep a final test partition untouched during preprocessing, feature selection, model fitting, alert threshold selection and hyperparameter tuning. Use validation data for those choices; refit transformations only on training data after choices are locked.
3. Make each model consume an immutable history slice ending at its forecast origin. Add a test that modifies or removes all future rows and proves predictions at that origin do not change.
4. Include no target columns, generator flags, future event times, future meal labels, latent “true glucose,” model-generated target state or test-subject metadata in predictor features.
5. For mechanistic predictions, distinguish parameters estimated from training subjects from known synthetic generator parameters. An ODE initialized with a hidden generator state is not observation-conditioned forecasting.
6. Report subject count, origins and target count by subject and horizon. Overlapping forecast windows are correlated; uncertainty intervals for aggregate metrics must resample subjects, not individual windows.

## Models And Baselines

Evaluate, on the same origin/target rows:

- **Persistence:** forecast the last valid historical glucose forward unchanged.
- **Linear trend:** fit a declared slope over a fixed, historical-only lookback and extrapolate; define behavior for insufficient, irregular or noisy histories before test.
- **Mechanistic ODE:** include only if equations, domain, input/observation model, initial-state estimation and parameters are scientifically interpretable for that task. Current default is excluded from physiological-prediction claims. Its synthetic continuation may appear only in Track C with an oracle/same-generator label.
- **Learned model:** include only if the eligible cohort size, subject diversity, sampling and covariate completeness support training without leakage. Fit all preprocessing/model choices inside the training/validation partitions. Do not add a model just because a framework is available.

Report the exact algorithm, lookback, parameters, training population and feature list. Compare against persistence first; linear trend is an additional simple comparator, not a guarantee of a stronger baseline.

## Metrics And Reporting

For each model, horizon and subject, report:

- Number of subjects, forecast origins and valid targets; target coverage/missingness; per-subject MAE and RMSE in mmol/L.
- Aggregate MAE and RMSE with subject-level uncertainty summaries, plus baseline-relative change computed on paired common targets. Report the sign convention and avoid aggregating windows as independent subjects.
- If a probabilistic forecast is supported, interval nominal level, empirical coverage and mean interval width by horizon and subject, with uncertainty based on subjects. Coverage on training data is not calibration evidence.
- Clearly name any range-occupancy metric as a predicted or observed fraction. It is not forecast accuracy. Event-risk evaluation is separate from glucose regression metrics.

The current reported RMSE 0.12 mmol/L must be recorded only as: one synthetic profile, 36 future samples at 5-minute spacing, one cutoff at 120 minutes, one 180-minute horizon, noisy observations generated by the same ODE, and an ODE forecast initialized from the generator's hidden state and exact parameters. It is not a subject-held-out estimate. The current forecast/baseline timestamps and units are aligned in that one run; the ODE's information advantage means the model comparison is not fair. No reported RMSE is evidence of level-3 performance until a suitable held-out measured cohort is evaluated.

## Event Evaluation

No calibrated risk probability is available in the present implementation. For any future event task, lock before test evaluation: event threshold, duration/continuity rule, forecast window, treatment of missing/intermittent samples, reference source and label adjudication. A deterministic mean-trajectory crossing is a threshold-crossing indicator, not a probability. A same-generator label is not independent ground truth.

Only with independent reference labels and adequate subject/event counts, report discrimination (e.g. sensitivity, specificity, AUROC/AUPRC), alert burden and lead time, plus probability calibration (Brier score/reliability and calibration uncertainty) on held-out subjects. Do not infer calibration from an ensemble's spread. Until these requirements are met, expose any threshold crossing as an **exploratory model-derived output**, not risk probability or treatment advice. Do not evaluate hypoglycemia on a domain where the physiological model is implausible.

## Synthetic Track Protocol

Synthetic tests may use the known latent output as generator truth, but must:

- Name the generator and parameter source; preserve a separate synthetic track and evaluation directory.
- Test deterministic seeds, unit handling, time alignment, observation noise, missingness behavior, metric calculations and recovery under controlled scenarios.
- Include held-out generator parameter/config families when testing generalization of code/model behavior; do not call these independent patients or independent physiological validation.
- Test coverage/recovery against both latent and noisy streams as separate quantities. Because the current base trajectory is included in its forecast ensemble, latent coverage on the same generator is mechanically guaranteed and is not an interval-calibration result.
- Never combine synthetic metrics with T1D/T2D measured-data metrics.

## Acceptance And Stop Conditions

- **Numerical software check:** reproducible output, correct units/alignment, no future-row dependence, valid metric calculations and solver invariants pass tests.
- **Physiological plausibility:** requires external physiological evidence and a declared range; not passed by this repository.
- **Held-out prediction:** requires a permissioned, representative measured cohort and subject-held-out results; currently blocked by absent data.
- **Clinical validation:** requires a distinct, appropriate clinical validation process and evidence; not claimed or addressed by the synthetic benchmark.

Stop model comparison when the data eligibility gate fails. In that case report the baselines as synthetic-method diagnostics only, record sample-size/data blockers, and seek permissioned data rather than inferring validation from generated trajectories.
